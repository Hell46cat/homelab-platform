# Карта технологий домашнего сервера и homelab

Этот документ — обзор карты технологий: что существует, какие задачи решает и где обычно применяется.

Он не является рекомендуемым стеком или чеклистом установки. Многие инструменты конкурируют между собой и решают одну задачу разными способами. Для конкретного проекта нужно выбирать минимальный подходящий набор, а перед установкой проверять актуальную документацию, поддержку и модель лицензирования.

---

## 1. Физическое оборудование

### Mini-PC

Компактный компьютер с низким энергопотреблением.

Используется для:

* Docker-контейнеров;
* Home Assistant;
* Telegram-ботов;
* небольших сайтов;
* мониторинга;
* VPN;
* локальных сервисов;
* нескольких виртуальных машин.

Плюсы:

* мало потребляет;
* почти не шумит;
* занимает мало места;
* достаточно мощный для большинства домашних задач.

Ограничения:

* мало мест для HDD;
* мало PCIe-слотов;
* сложнее превратить в полноценный NAS;
* иногда ограниченное охлаждение.

---

### Корпоративный mini-PC

Примеры:

* Lenovo ThinkCentre Tiny;
* Dell OptiPlex Micro;
* HP EliteDesk Mini.

Используется как недорогой и надёжный домашний сервер.

Особенности:

* обычно сменная RAM;
* NVMe и иногда SATA;
* хороший BIOS;
* нормальное охлаждение;
* много предложений на вторичном рынке.

---

### Обычный ПК или mATX-сборка

Полноценный компьютер в обычном корпусе.

Используется, когда нужны:

* несколько HDD;
* видеокарта;
* PCIe-сетевые карты;
* HBA-контроллер;
* расширение RAM;
* объединение NAS и сервера приложений.

Потребляет больше mini-PC, но значительно лучше расширяется.

---

### Старое серверное железо

Примеры:

* Dell PowerEdge;
* HP ProLiant;
* Supermicro;
* старые Xeon-сборки.

Используется для:

* большого количества дисков;
* ECC-памяти;
* IPMI;
* нескольких сетевых карт;
* изучения серверного оборудования;
* виртуализации большого числа VM.

Для обычного домашнего сервера часто избыточно из-за:

* шума;
* энергопотребления;
* размеров;
* старого и неэффективного железа.

---

### Raspberry Pi и одноплатные компьютеры

Примеры:

* Raspberry Pi;
* Orange Pi;
* Radxa;
* Rock Pi.

Используются для:

* Home Assistant;
* сетевых сервисов;
* DNS;
* MQTT;
* управления 3D-принтером;
* небольших устройств рядом с оборудованием.

Ограничения:

* ARM-архитектура;
* слабее обычного x86 mini-PC;
* microSD нежелательна для постоянных записей;
* ограниченное расширение.

---

## 2. Базовая операционная система

### Debian

Стабильный минималистичный Linux-дистрибутив.

Используется как:

* Docker-хост;
* сервер приложений;
* база для виртуальных машин;
* NAS-сервер;
* сервер разработки.

Плюсы:

* стабильность;
* мало лишнего;
* предсказуемые обновления;
* огромное количество пакетов;
* хорошая документация.

Хороший выбор для сервера, который должен долго работать без лишних изменений.

---

### Ubuntu Server

Серверная версия Ubuntu без графического интерфейса.

Используется для:

* Docker;
* серверов приложений;
* облачных серверов;
* Kubernetes;
* CI/CD;
* домашних серверов.

Плюсы:

* много инструкций;
* хорошая поддержка нового железа;
* удобная установка;
* популярность в коммерческой инфраструктуре.

По назначению очень близка к Debian.

---

### Rocky Linux / AlmaLinux

Дистрибутивы, совместимые с экосистемой Red Hat Enterprise Linux.

Используются:

* в корпоративной инфраструктуре;
* для изучения RHEL-подобных систем;
* на серверах с `dnf`, SELinux и RPM-пакетами.

Для первого домашнего Docker-хоста обычно сложнее Debian или Ubuntu без очевидной выгоды.

---

### Fedora Server

Современный серверный Linux с быстрым обновлением технологий.

Используется для:

* изучения новых Linux-технологий;
* Podman;
* SELinux;
* тестовых серверов.

Для постоянно работающего homelab требует более частого обновления.

---

### Arch Linux

Rolling-release дистрибутив.

Используется энтузиастами, которые хотят:

* самые новые версии пакетов;
* полностью контролировать систему;
* глубоко изучать Linux.

Для домашнего сервера может потребовать слишком много сопровождения.

---

### NixOS

Linux-дистрибутив с декларативной конфигурацией системы.

Состояние сервера описывается конфигурационными файлами: packages, services, users, networking и другие параметры можно воспроизводить и хранить в Git.

Полезен для:

* изучения declarative infrastructure;
* повторяемой настройки серверов;
* rollback между поколениями конфигурации;
* лабораторий, где важна воспроизводимость.

Имеет заметный порог входа и не обязателен для первого домашнего сервера.

---

### Alpine Linux

Очень компактный Linux.

Чаще используется:

* внутри Docker-образов;
* в минимальных контейнерах;
* в небольших виртуальных системах.

Как основной сервер может создавать дополнительные сложности из-за `musl` вместо `glibc`.

---

## 3. Виртуализация

### Proxmox VE

Гипервизор на базе Debian.

Позволяет запускать:

* виртуальные машины KVM;
* LXC-контейнеры;
* виртуальные сети;
* snapshots;
* резервные копии;
* кластеры.

Используется, когда на одном сервере нужны разные независимые системы:

* Home Assistant OS;
* Debian с Docker;
* Windows;
* OpenWrt;
* OPNsense;
* тестовые Linux VM.

Proxmox не обязателен, если все сервисы можно держать в Docker на одной ОС.

---

### KVM / QEMU

Базовые технологии виртуализации Linux.

KVM отвечает за аппаратную виртуализацию, QEMU — за эмуляцию оборудования.

Используются внутри:

* Proxmox;
* libvirt;
* многих облачных платформ.

---

### libvirt

Система управления виртуальными машинами KVM/QEMU.

Инструменты:

* `virsh`;
* Virt-Manager;
* Cockpit Machines.

Подходит, если нужны VM без полноценного Proxmox.

---

### VMware ESXi

Коммерческий гипервизор.

Используется в корпоративной виртуализации.

Особенности:

* развитая экосистема;
* сильная интеграция с VMware;
* лицензирование;
* для домашнего использования сейчас менее привлекателен, чем Proxmox.

---

### Hyper-V

Гипервизор Microsoft.

Используется:

* в Windows Server;
* Windows Pro;
* корпоративной инфраструктуре;
* для запуска Windows и Linux VM.

---

### XCP-ng

Открытый гипервизор на основе Xen.

Используется как альтернатива Proxmox и VMware.

Обычно управляется через Xen Orchestra.

---

### LXC

Системные Linux-контейнеры.

В отличие от Docker, LXC-контейнер больше похож на отдельную лёгкую Linux-систему.

Используется для:

* изолированных сервисов;
* полноценных Linux-окружений;
* экономии ресурсов по сравнению с VM.

---

### Incus

Менеджер системных контейнеров и виртуальных машин.

Предоставляет единый API и CLI для Linux system containers, VM, images, storage и networking. Может работать на одном хосте или в кластере.

Полезен, если нужны лёгкие Linux-окружения и VM без полноценной панели Proxmox.

Incus управляет инфраструктурными окружениями, а Docker обычно упаковывает и запускает отдельные приложения.

---

## 4. Контейнеризация

### Docker

Платформа для запуска приложений в контейнерах.

Контейнер содержит:

* приложение;
* зависимости;
* файловую систему;
* переменные окружения;
* сетевые настройки.

Используется для:

* ботов;
* сайтов;
* баз данных;
* Home Assistant;
* ESPHome;
* мониторинга;
* reverse proxy;
* большинства self-hosted приложений.

---

### Dockerfile

Файл с инструкциями сборки Docker-образа.

Описывает:

* базовый образ;
* копирование исходников;
* установку зависимостей;
* сборку приложения;
* команду запуска.

Пример назначения:

```text
Исходники Go → Dockerfile → Docker image → container
```

---

### Docker image

Неизменяемый шаблон контейнера.

Содержит приложение и его зависимости.

Из одного образа можно запустить несколько контейнеров.

---

### Docker container

Запущенный экземпляр Docker-образа.

Контейнер можно:

* запускать;
* останавливать;
* удалять;
* пересоздавать;
* масштабировать.

---

### Docker Compose

Инструмент декларативного описания нескольких контейнеров.

Файл `compose.yaml` описывает:

* services;
* networks;
* volumes;
* ports;
* environment;
* healthchecks;
* зависимости.

Используется для запуска целого стека одной командой:

```text
Приложение + PostgreSQL + Redis + reverse proxy
```

---

### Docker volume

Хранилище постоянных данных Docker.

Используется для:

* данных PostgreSQL;
* конфигурации Grafana;
* данных Portainer;
* состояния приложений.

Volume не удаляется при пересоздании контейнера, если его не удалить явно.

---

### Bind mount

Подключение обычной папки хоста внутрь контейнера.

Пример:

```text
/srv/home-lab/app/config → /config внутри контейнера
```

Используется для:

* исходников;
* YAML-конфигураций;
* Compose-проектов;
* файлов, которые нужно редактировать с хоста.

---

### Docker network

Виртуальная сеть для контейнеров.

Позволяет контейнерам обращаться друг к другу по имени сервиса:

```text
app → postgres:5432
```

---

### Docker Registry

Хранилище Docker-образов.

Примеры:

* Docker Hub;
* GitHub Container Registry;
* GitLab Container Registry;
* Harbor;
* локальный Docker Registry.

Используется для публикации и доставки образов.

---

### OCI

Open Container Initiative — набор открытых спецификаций для:

* формата container images;
* запуска контейнеров;
* распространения artifacts через registry.

Благодаря OCI один и тот же image может использоваться разными совместимыми инструментами, а контейнерная экосистема не привязана только к Docker.

---

### BuildKit и Docker Buildx

BuildKit — движок сборки images, который используется современным Docker.

Возможности:

* эффективный layer cache;
* параллельное выполнение независимых стадий;
* cache import/export;
* build secrets и SSH mounts;
* rootless execution;
* разные форматы результата.

`docker buildx` — CLI-плагин, через который удобно использовать BuildKit, multi-platform builds и дополнительные builders.

---

### Harbor

Полноценный self-hosted OCI registry.

Дополняет хранение images функциями:

* RBAC и проекты;
* vulnerability scanning;
* replication между registry;
* audit;
* garbage collection;
* интеграция с LDAP и OIDC.

Для небольшой лаборатории обычного registry часто достаточно. Harbor полезен для изучения более корпоративной цепочки доставки.

---

### Podman

Альтернатива Docker.

Особенности:

* может работать без root;
* не требует постоянного daemon;
* совместим со многими Docker-командами;
* популярен в Red Hat-экосистеме.

---

### containerd

Низкоуровневая среда запуска контейнеров.

Используется внутри:

* Docker;
* Kubernetes;
* других контейнерных платформ.

Обычный пользователь редко работает с ним напрямую.

---

## 5. Управление контейнерами

### Portainer

Веб-интерфейс для Docker и Kubernetes.

Позволяет:

* смотреть контейнеры;
* запускать и останавливать их;
* смотреть логи;
* открывать консоль;
* управлять images;
* управлять networks;
* управлять volumes;
* разворачивать Compose как Stacks.

Удобен как UI, но не должен заменять хранение конфигурации в `compose.yaml`.

---

### Coolify

Self-hosted PaaS, похожая по назначению на Heroku, Netlify или Vercel.

Управляет серверами по SSH и помогает разворачивать:

* приложения из Git;
* Docker workloads;
* базы данных;
* domains и TLS;
* preview deployments.

Удобна для быстрого hosting приложений, но скрывает часть ручной настройки. Поэтому для обучения Linux, Docker и reverse proxy её полезнее изучать после базовых слоёв.

---

### Dockge

Лёгкий веб-интерфейс для Docker Compose.

Ориентирован именно на управление Compose-стеками.

Проще Portainer, если нужны только:

* просмотр Compose;
* запуск;
* остановка;
* редактирование;
* логи.

---

### Yacht

Ещё один веб-интерфейс управления контейнерами.

Менее распространён, чем Portainer.

---

### Lazydocker

Терминальный интерфейс для Docker.

Позволяет быстро смотреть:

* контейнеры;
* логи;
* образы;
* volumes;
* состояние Compose.

Работает прямо в терминале.

---

## 6. Оркестрация контейнеров

### Docker Swarm

Встроенный оркестратор Docker.

Используется для:

* нескольких Docker-узлов;
* replicated services;
* service discovery;
* rolling updates;
* overlay networks.

Проще Kubernetes, но значительно реже используется в новых проектах.

---

### Kubernetes

Платформа оркестрации контейнеров.

Управляет:

* Pods;
* Deployments;
* Services;
* Ingress;
* ConfigMaps;
* Secrets;
* persistent volumes;
* масштабированием;
* обновлениями.

Используется в крупной инфраструктуре и облаках.

Для небольшого домашнего сервера часто избыточен, но полезен для обучения.

---

### k3s

Облегчённый Kubernetes-дистрибутив.

Используется:

* в homelab;
* на edge-устройствах;
* на небольших кластерах;
* на Raspberry Pi;
* для изучения Kubernetes.

Проще развернуть, чем обычный Kubernetes.

---

### MicroK8s

Компактная сборка Kubernetes от Canonical.

Подходит для:

* локальной разработки;
* Ubuntu;
* тестовых кластеров;
* небольшого homelab.

---

### Minikube

Локальный одноузловой Kubernetes.

Используется в основном для разработки и обучения на одном компьютере.

---

### Talos Linux

Минималистичная операционная система специально для Kubernetes.

Управляется через API, не предназначена для обычной ручной работы по SSH.

Используется в специализированных Kubernetes-кластерах.

---

### Helm

Пакетный менеджер Kubernetes.

Helm chart описывает набор Kubernetes-ресурсов приложения.

Аналогия:

```text
Docker Compose для Kubernetes, но сложнее и мощнее
```

---

### Argo CD

GitOps-инструмент для Kubernetes.

Следит за Git-репозиторием и приводит кластер к описанному состоянию.

---

### Flux CD

Ещё один GitOps-инструмент для Kubernetes.

Похож по назначению на Argo CD.

---

## 7. Удалённое управление сервером

### SSH

Основной способ удалённого управления Linux-сервером.

Используется для:

* терминала;
* запуска команд;
* копирования файлов;
* Git;
* туннелей;
* удалённой разработки.

---

### OpenSSH

Самая распространённая реализация SSH.

Состоит из:

* SSH-клиента;
* SSH-сервера;
* SCP;
* SFTP;
* SSH-key authentication.

---

### Remote SSH

Функция VS Code и Cursor.

Позволяет работать с сервером так, будто проект находится локально:

* редактировать файлы;
* запускать терминал;
* использовать Git;
* запускать тесты;
* работать с Docker.

---

### Cockpit

Веб-интерфейс управления Linux-сервером.

Позволяет смотреть:

* CPU;
* RAM;
* диски;
* systemd services;
* логи;
* сеть;
* обновления;
* виртуальные машины.

Это не замена SSH, а дополнительная панель администрирования.

---

### Webmin

Старый универсальный веб-интерфейс управления Linux.

Позволяет настраивать множество системных сервисов.

Сегодня используется реже, чем раньше.

---

### mosh

Альтернатива SSH для нестабильных соединений.

Лучше переживает:

* обрывы;
* смену IP;
* плохую мобильную сеть.

---

## 8. Доступ к файлам

### Samba

Реализация SMB-протокола для Linux.

Позволяет открыть Linux-папку в Windows:

```text
\\server\projects
```

Используется для:

* документов;
* медиа;
* общих файлов;
* обмена между Windows и Linux.

---

### SMB

Сетевой файловый протокол Windows.

Используется в:

* Windows-шарах;
* Samba;
* NAS;
* корпоративных файловых серверах.

---

### NFS

Сетевой файловый протокол, распространённый в Linux и Unix.

Используется для:

* Linux-серверов;
* виртуализации;
* Kubernetes;
* общих каталогов между Linux-машинами.

Для Windows обычно удобнее SMB.

---

### SFTP

Передача файлов поверх SSH.

Используется для:

* безопасной загрузки файлов;
* файловых клиентов;
* автоматизации;
* удалённой разработки.

---

### SCP

Простое копирование файлов через SSH.

Пример назначения:

```text
Локальный файл → сервер
```

---

### rsync

Инструмент синхронизации файлов.

Передаёт только изменившиеся части файлов.

Используется для:

* копирования;
* резервных копий;
* синхронизации серверов;
* деплоя.

---

### Syncthing

Peer-to-peer синхронизация папок между устройствами.

Используется для:

* документов;
* заметок;
* фотографий;
* проектов;
* обмена между ПК, ноутбуком, телефоном и сервером.

Синхронизация не является полноценным резервным копированием без версионирования.

---

### Nextcloud

Self-hosted аналог облачного диска.

Возможности:

* файлы;
* пользователи;
* ссылки;
* WebDAV;
* календарь;
* контакты;
* мобильные клиенты.

Тяжелее Syncthing, но предоставляет полноценный веб-сервис.

---

### File Browser

Лёгкий веб-файловый менеджер.

Позволяет работать с файлами сервера через браузер.

---

## 9. Хранилища и NAS

### NAS

Network Attached Storage — сетевое хранилище.

Используется для:

* файлов;
* фотографий;
* видео;
* резервных копий;
* камер;
* медиатеки;
* общих сетевых папок.

---

### TrueNAS SCALE

Операционная система для NAS на основе Linux.

Возможности:

* ZFS;
* SMB;
* NFS;
* snapshots;
* RAIDZ;
* управление дисками;
* приложения;
* репликация.

Хорошо подходит для отдельного NAS-сервера.

---

### TrueNAS CORE

Версия TrueNAS на базе FreeBSD.

Исторически очень популярна для ZFS-хранилищ.

SCALE обычно удобнее, если нужна Linux-экосистема и контейнеры.

---

### OpenMediaVault

NAS-система на базе Debian.

Проще TrueNAS.

Используется для:

* SMB;
* NFS;
* дисков;
* пользователей;
* небольших домашних NAS.

---

### Unraid

Коммерческая NAS-операционная система.

Особенности:

* диски разного размера;
* parity-диски;
* Docker;
* виртуальные машины;
* простой UI.

Не использует классический RAID как основную модель.

---

### XigmaNAS

NAS-система на базе FreeBSD.

Менее популярна, чем TrueNAS.

---

### ZFS

Файловая система и менеджер томов.

Возможности:

* checksums;
* snapshots;
* compression;
* replication;
* RAIDZ;
* обнаружение повреждений;
* copy-on-write.

Используется в NAS и серьёзных хранилищах.

---

### Btrfs

Современная Linux-файловая система.

Возможности:

* snapshots;
* checksums;
* compression;
* subvolumes;
* встроенный RAID.

Часто используется в Linux-системах и некоторых NAS.

---

### ext4

Стандартная и очень стабильная Linux-файловая система.

Хороший выбор для:

* системного SSD;
* Docker-хоста;
* обычных серверных данных.

Не имеет встроенных snapshots и checksums данных, как ZFS.

---

### XFS

Производительная Linux-файловая система.

Используется:

* на серверах;
* в больших файловых системах;
* в enterprise Linux.

---

### RAID

Объединение нескольких дисков.

Основные варианты:

* RAID 0 — скорость, нет отказоустойчивости;
* RAID 1 — зеркалирование;
* RAID 5 — один диск чётности;
* RAID 6 — два диска чётности;
* RAID 10 — зеркала и чередование.

RAID не является резервной копией.

---

### RAIDZ

Вариант RAID внутри ZFS.

Типы:

* RAIDZ1 — отказ одного диска;
* RAIDZ2 — отказ двух дисков;
* RAIDZ3 — отказ трёх дисков.

---

### mdadm

Linux-инструмент программного RAID.

Используется для создания RAID-массивов без ZFS.

---

### LVM

Logical Volume Manager.

Позволяет:

* объединять диски;
* создавать логические тома;
* изменять размеры;
* делать snapshots.

Часто используется в Linux-серверах.

---

### HBA

Host Bus Adapter — контроллер подключения большого количества SATA/SAS-дисков.

Используется в NAS и файловых серверах.

Для ZFS HBA обычно переводят в IT mode, чтобы ОС видела каждый диск напрямую.

---

### SMART

Система диагностики состояния HDD и SSD.

Показывает:

* ошибки;
* температуру;
* часы работы;
* переназначенные сектора;
* износ SSD.

Инструмент Linux:

```text
smartctl
```

---

### Scrutiny

Веб-интерфейс для мониторинга S.M.A.R.T. показателей дисков.

Помогает:

* видеть состояние HDD и SSD;
* хранить историю показателей;
* замечать ухудшение параметров;
* получать уведомления о проблемах.

Не заменяет backup и не гарантирует предсказание всех отказов.

---

### mergerfs

Объединяет несколько файловых систем и дисков в единое логическое дерево каталогов.

Часто используется в домашних media storage, когда нужны:

* диски разного размера;
* постепенное расширение;
* обычные файловые системы под слоем объединения.

Сам по себе не создаёт redundancy и не заменяет RAID или backup.

---

### SnapRAID

Создаёт parity для набора дисков с данными.

Особенности:

* работает поверх обычных файловых систем;
* допускает диски разного размера;
* parity обновляется по расписанию, а не синхронно с каждой записью;
* чаще подходит для относительно редко меняющихся media collections.

Это не real-time RAID и не резервная копия важных данных. Часто используется вместе с mergerfs.

---

## 10. Объектное хранилище

### S3

Протокол объектного хранения, появившийся в AWS.

Данные хранятся как объекты внутри buckets.

Используется для:

* файлов приложений;
* фотографий;
* архивов;
* резервных копий;
* пользовательских загрузок.

---

### MinIO

Self-hosted S3-совместимое хранилище.

Используется для:

* разработки приложений;
* локального S3;
* хранения файлов;
* резервных копий;
* распределённого object storage.

---

### Ceph

Распределённая система хранения.

Предоставляет:

* object storage;
* block storage;
* файловую систему.

Используется в больших кластерах и облаках.

Для одного домашнего сервера обычно слишком сложна.

---

### SeaweedFS

Распределённая файловая и объектная система.

Проще некоторых сценариев Ceph, но тоже ориентирована на несколько узлов.

---

## 11. Сети

### Ethernet

Проводная локальная сеть.

Для серверов предпочтительнее Wi-Fi из-за:

* стабильности;
* меньшей задержки;
* предсказуемой скорости;
* отсутствия проблем с радиосигналом.

---

### 1GbE

Гигабитная сеть.

Реальная скорость передачи файлов обычно около 100–115 МБ/с.

Достаточна для большинства домашних задач.

---

### 2.5GbE

Сеть 2.5 Гбит/с.

Реальная скорость может достигать примерно 250–280 МБ/с.

Полезна для:

* NAS;
* больших файлов;
* резервных копий;
* нескольких камер;
* быстрой работы с сервером.

---

### 10GbE

Сеть 10 Гбит/с.

Используется для:

* быстрых NAS;
* больших массивов;
* видеомонтажа;
* серверных кластеров.

Для небольшого homelab часто избыточна.

---

### DHCP

Протокол автоматической выдачи IP-адресов.

Обычно работает на роутере.

Для сервера полезно настроить DHCP reservation, чтобы он всегда получал один адрес.

---

### DNS

Преобразует имена в IP-адреса.

Пример:

```text
grafana.home → 192.168.1.50
```

---

### VLAN

Логическое разделение одной физической сети.

Пример:

```text
VLAN 10 — основные устройства
VLAN 20 — серверы
VLAN 30 — IoT
VLAN 40 — камеры
VLAN 50 — гости
```

Используется для безопасности и изоляции.

---

### Firewall

Фильтрует сетевой трафик.

Решает:

* кто к кому может подключаться;
* какие порты открыты;
* какие сети изолированы;
* что доступно из интернета.

---

### nftables

Современная система firewall в Linux.

Заменила большую часть использования `iptables`.

---

### iptables

Классический инструмент Linux firewall.

До сих пор широко встречается, но постепенно уступает nftables.

---

### UFW

Упрощённый интерфейс управления firewall.

Часто используется в Ubuntu.

---

### OpenWrt

Linux-дистрибутив для роутеров.

Позволяет настраивать:

* VLAN;
* WireGuard;
* firewall;
* QoS;
* DNS;
* дополнительные пакеты;
* несколько сетей.

Подходит для отдельного физического роутера или виртуальной машины.

---

### OPNsense

Firewall и маршрутизатор на базе FreeBSD.

Используется как:

* основной роутер;
* firewall;
* VPN-шлюз;
* VLAN-маршрутизатор;
* IDS/IPS.

Обычно требует отдельного устройства с несколькими сетевыми интерфейсами.

---

### pfSense

Похожая система маршрутизации и firewall.

Исторически очень популярна.

OPNsense и pfSense являются основными конкурентами.

---

### VyOS

Сетевая операционная система с интерфейсом командной строки.

Используется для:

* маршрутизации;
* VPN;
* BGP;
* OSPF;
* сложных сетевых лабораторий.

---

### UniFi

Экосистема сетевого оборудования Ubiquiti.

Включает:

* точки доступа;
* коммутаторы;
* роутеры;
* контроллер;
* камеры.

Популярна в продвинутых домашних сетях.

---

### MikroTik RouterOS

Операционная система роутеров MikroTik.

Поддерживает:

* VLAN;
* firewall;
* VPN;
* routing;
* QoS;
* CAPsMAN.

Очень мощная, но имеет специфичный интерфейс и терминологию.

---

## 12. VPN и удалённый доступ

### WireGuard

Современный быстрый VPN.

Используется для:

* доступа к домашней сети;
* соединения серверов;
* защиты удалённого трафика;
* site-to-site VPN.

---

### Tailscale

Overlay-сеть поверх WireGuard.

Упрощает подключение устройств без ручной настройки маршрутов и проброса портов.

Подходит для:

* телефона;
* ноутбука;
* домашнего сервера;
* удалённого доступа;
* CGNAT.

---

### Headscale

Self-hosted управляющий сервер, совместимый с клиентами Tailscale.

Используется, если хочется меньше зависеть от облачного control plane Tailscale.

---

### NetBird

Mesh VPN на базе WireGuard.

Предоставляет:

* автоматическое соединение устройств;
* access policies;
* routes в локальные подсети;
* DNS-настройки;
* managed и self-hosted control plane.

По классу задач похож на Tailscale и полезен как альтернативный пример организации overlay network.

---

### ZeroTier

Альтернатива Tailscale.

Создаёт виртуальную сеть между устройствами.

---

### OpenVPN

Старый и очень распространённый VPN.

Гибкий, но обычно сложнее и медленнее WireGuard.

---

### Cloudflare Tunnel

Создаёт исходящее соединение от сервера к Cloudflare.

Позволяет публиковать веб-сервисы без прямого проброса портов.

Не заменяет полноценный VPN для доступа ко всей домашней сети.

---

## 13. Reverse proxy и веб-доступ

### Reverse proxy

Принимает веб-запросы и направляет их к нужному приложению.

Пример:

```text
grafana.home → Grafana:3000
git.home → Gitea:3000
ha.home → Home Assistant:8123
```

---

### Nginx

Популярный веб-сервер и reverse proxy.

Используется для:

* TLS;
* маршрутизации;
* статических файлов;
* load balancing;
* кеширования.

Надёжный, но конфигурация может быть многословной.

---

### Caddy

Современный веб-сервер и reverse proxy.

Преимущества:

* простая конфигурация;
* автоматический HTTPS;
* удобен для небольшого homelab.

---

### Traefik

Reverse proxy, ориентированный на контейнеры.

Может автоматически находить Docker-сервисы по labels.

Используется в:

* Docker;
* Kubernetes;
* динамической инфраструктуре.

---

### HAProxy

Высокопроизводительный load balancer и proxy.

Используется в:

* балансировке;
* высоконагруженной инфраструктуре;
* TCP и HTTP proxy.

---

### Nginx Proxy Manager

Веб-интерфейс для настройки Nginx reverse proxy.

Удобен для новичков.

Позволяет создавать proxy hosts и сертификаты через GUI.

---

### Envoy

Современный proxy для микросервисов.

Используется в:

* service mesh;
* Kubernetes;
* API gateways;
* сложной сетевой инфраструктуре.

Для простого homelab обычно избыточен.

---

## 14. TLS и сертификаты

### HTTPS

Зашифрованный HTTP.

Используется для безопасного доступа к веб-интерфейсам и API.

---

### TLS

Протокол шифрования, используемый HTTPS.

---

### Let's Encrypt

Бесплатный центр сертификации.

Выдаёт публично доверенные TLS-сертификаты.

---

### ACME

Протокол автоматической выдачи и обновления сертификатов.

Поддерживается:

* Caddy;
* Traefik;
* Certbot;
* Nginx Proxy Manager.

---

### Certbot

Клиент для получения сертификатов Let's Encrypt.

Часто используется вместе с Nginx или Apache.

---

### mkcert

Инструмент создания локально доверенных сертификатов.

Удобен для внутренних доменов и разработки.

---

### step-ca

Self-hosted центр сертификации.

Используется для собственной внутренней PKI.

---

## 15. Локальный DNS и блокировка рекламы

### AdGuard Home

Локальный DNS-сервер с блокировкой рекламы и трекеров.

Используется для:

* фильтрации DNS;
* статистики;
* родительского контроля;
* локальных DNS-записей;
* защиты устройств.

---

### Pi-hole

Популярный DNS-фильтр для домашней сети.

Похож по назначению на AdGuard Home.

---

### Technitium DNS Server

Self-hosted authoritative и recursive DNS server с веб-интерфейсом.

Поддерживает:

* локальные DNS zones;
* DNS blocking;
* recursive resolution;
* DNS-over-HTTPS, DNS-over-TLS и DNS-over-QUIC;
* logs и статистику запросов;
* запуск в Docker.

Это более универсальный DNS-сервер, чем простой блокировщик рекламы, но и возможностей для настройки у него больше.

---

### Unbound

Рекурсивный DNS resolver.

Может самостоятельно запрашивать DNS-иерархию без публичных DNS-провайдеров.

Часто используется вместе с Pi-hole или AdGuard Home.

---

### dnsmasq

Лёгкий DNS и DHCP-сервер.

Часто встроен в роутеры и OpenWrt.

---

### CoreDNS

Гибкий DNS-сервер.

Широко используется внутри Kubernetes.

---

## 16. Умный дом

### Home Assistant

Центральная платформа умного дома.

Объединяет:

* датчики;
* свет;
* розетки;
* камеры;
* климат;
* автоматизации;
* уведомления;
* dashboards.

---

### Home Assistant OS

Готовая операционная система для Home Assistant.

Содержит:

* Home Assistant Core;
* Supervisor;
* add-ons;
* backups;
* обновления.

Обычно запускается:

* на отдельном mini-PC;
* Raspberry Pi;
* виртуальной машине.

---

### Home Assistant Container

Home Assistant внутри Docker.

Подходит, если остальная инфраструктура уже управляется через Docker Compose.

Нет встроенного Supervisor и магазина add-ons в том же виде, как в HA OS.

---

### Home Assistant Core

Само приложение Home Assistant без ОС и Supervisor.

---

### ESPHome

Система создания прошивок для ESP8266 и ESP32 через YAML.

Используется для:

* датчиков;
* реле;
* света;
* дисплеев;
* климатических устройств;
* пользовательских IoT-устройств.

После первичной USB-прошивки обновления обычно выполняются по OTA.

---

### ESP32

Микроконтроллер с Wi-Fi и Bluetooth.

Используется в самодельных устройствах:

* датчики температуры;
* управление светом;
* реле;
* Bluetooth proxy;
* контроллеры;
* дисплеи.

---

### ESP8266

Предыдущее поколение Wi-Fi-микроконтроллеров.

Дешёвый, но слабее ESP32.

---

### MQTT

Лёгкий протокол обмена сообщениями.

Модель:

```text
Publisher → Broker → Subscriber
```

Используется в:

* IoT;
* умном доме;
* датчиках;
* телеметрии;
* событиях.

---

### Mosquitto

Популярный MQTT broker.

Принимает и распределяет MQTT-сообщения.

Используется вместе с:

* Home Assistant;
* ESPHome;
* Zigbee2MQTT;
* пользовательскими устройствами;
* Go-сервисами.

---

### EMQX

Более мощный MQTT broker.

Подходит для:

* большого количества устройств;
* кластеризации;
* расширенной аналитики;
* enterprise IoT.

Для дома Mosquitto обычно проще.

---

### Zigbee

Беспроводной протокол для IoT-устройств.

Используется в:

* датчиках;
* лампах;
* розетках;
* кнопках;
* термостатах.

Создаёт mesh-сеть.

---

### Zigbee2MQTT

Связывает Zigbee-устройства с MQTT.

Требует Zigbee-координатор.

Позволяет использовать устройства разных производителей без фирменных облаков.

---

### ZHA

Встроенная интеграция Zigbee в Home Assistant.

Альтернатива Zigbee2MQTT.

Проще по архитектуре, но Zigbee2MQTT часто даёт больше гибкости и поддерживаемых настроек.

---

### Z-Wave

Другой беспроводной протокол для умного дома.

Популярен в США и Европе.

Устройства обычно дороже Zigbee, но экосистема стандартизирована.

---

### Thread

Современный mesh-протокол на базе IPv6.

Используется в экосистеме Matter.

---

### Matter

Стандарт совместимости устройств умного дома.

Должен упростить работу устройств разных производителей.

Может использовать Thread, Wi-Fi и Ethernet.

---

### Bluetooth Proxy

ESP32 или другое устройство передаёт Bluetooth-сигналы в Home Assistant.

Полезно, если сервер находится далеко от Bluetooth-датчиков.

---

### Node-RED

Визуальный редактор потоков автоматизации.

Используется для:

* IoT;
* MQTT;
* Home Assistant;
* API;
* интеграций;
* обработки событий.

---

### n8n

Визуальная платформа автоматизации workflows.

Используется для:

* Telegram;
* API;
* почты;
* баз данных;
* AI;
* webhooks;
* бизнес-автоматизации;
* домашних сценариев.

Node-RED больше ориентирован на IoT и события, n8n — на сервисы, API и бизнес-процессы.

---

## 17. Камеры и видеонаблюдение

### RTSP

Протокол передачи видеопотока.

Поддерживается большинством IP-камер.

---

### ONVIF

Стандарт обнаружения и управления IP-камерами.

Используется для:

* поиска камер;
* получения потоков;
* PTZ;
* событий;
* совместимости разных производителей.

---

### NVR

* кластер для больших объёмов;

## 19. Логи

### systemd-journald

Штатная система сбора логов в дистрибутивах с systemd.

Получает сообщения от:

* systemd services;
* kernel;
* stdout/stderr процессов;
* syslog-compatible приложений.

Просмотр и фильтрация выполняются через `journalctl`.

Это первый источник логов, который стоит освоить до установки Loki или ELK.

---

### rsyslog

Реализация протокола syslog.

Используется для:

* записи логов в файлы;
* фильтрации сообщений;
* пересылки логов на удалённый сервер;
* приёма логов от сетевых устройств.

Полезен для понимания классической Linux logging pipeline.

---

### Loki

Система хранения логов от Grafana Labs.

Индексирует labels, а не полный текст всех сообщений.

Часто используется вместе с Grafana.

---

### Promtail

Старый агент доставки логов в Loki.

Собирает логи из файлов и контейнеров.

---

### Grafana Alloy

Современный агент Grafana для:

* metrics;
* logs;
* traces;
* OpenTelemetry.

Может заменять несколько отдельных агентов.

---

### ELK Stack

Набор:

* Elasticsearch;
* Logstash;
* Kibana.

Используется для централизованных логов и поиска.

Мощный, но тяжёлый по ресурсам.

---

### OpenSearch

Open-source поисковая система, появившаяся как ответвление Elasticsearch.

Используется для:

* логов;
* поиска;
* аналитики.

---

### Fluent Bit

Лёгкий агент сбора логов.

Используется в Docker и Kubernetes.

---

### Fluentd

Более тяжёлая и расширяемая система обработки логов.

---

### Vector

Высокопроизводительный агент сбора и преобразования:

* логов;
* метрик;
* событий.

---

## 43. Диагностика и повседневная эксплуатация

### `curl`

HTTP-клиент командной строки.

Используется для проверки:

* API;
* headers;
* redirects;
* TLS;
* health endpoints;
* доступности сервиса из разных сетевых точек.

---

### `dig` и `nslookup`

Инструменты диагностики DNS.

Показывают:

* какой DNS server ответил;
* полученные records;
* время ответа;
* authoritative информацию;
* ошибки разрешения имён.

`dig` обычно даёт более подробный и удобный для диагностики вывод.

---

### `ss`

Показывает network sockets Linux.

Помогает понять:

* какие порты слушает сервер;
* на каких адресах они открыты;
* какие TCP-соединения установлены;
* какой процесс владеет socket.

Современная замена многим сценариям старого `netstat`.

---

### `ping`, `traceroute` и `mtr`

Инструменты проверки сетевого пути.

* `ping` проверяет IP-доступность и задержку;
* `traceroute` показывает последовательность маршрутизаторов;
* `mtr` совмещает traceroute с длительным измерением задержки и потерь.

Отсутствие ответа на `ping` не всегда означает недоступность сервиса: ICMP может быть заблокирован.

---

### `tcpdump`

CLI packet analyzer.

Позволяет захватывать и фильтровать traffic непосредственно на Linux-сервере.

Используется для диагностики:

* DNS;
* TCP handshakes;
* DHCP;
* маршрутизации;
* неожиданных соединений.

Захват может содержать чувствительные данные, поэтому pcap-файлы нельзя бездумно публиковать.

---

### Wireshark

Графический анализатор сетевых пакетов.

Открывает live capture или pcap-файлы от `tcpdump`, декодирует протоколы и помогает подробно исследовать сетевой обмен.

---

### `iperf3`

Измеряет пропускную способность сети между двумя узлами.

Полезен для проверки:

* Ethernet и Wi-Fi;
* 1/2.5/10 GbE;
* VLAN;
* VPN;
* влияния CPU и шифрования на скорость.

Проверяет именно сеть, не смешивая результат со скоростью дисков или файловых протоколов.

---

### `nc` / netcat

Простой инструмент чтения и записи TCP/UDP connections.

Используется для:

* проверки доступности порта;
* временного listener;
* передачи тестовых данных;
* изучения простых сетевых протоколов.

---

### `lsof` и `fuser`

Показывают, какие процессы используют файлы, mounts и network ports.

Полезны, когда:

* порт уже занят;
* каталог не удаётся размонтировать;
* файл удерживается процессом;
* нужно найти владельца ресурса.

---

### `htop` и `btop`

Интерактивные инструменты наблюдения за процессами и ресурсами.

Показывают CPU, RAM, load average и процессы. Удобны для первичного осмотра, но не заменяют исторические метрики Prometheus.

---

### `jq` и `yq`

CLI-инструменты обработки структурированных данных:

* `jq` — JSON;
* `yq` — YAML.

Полезны в shell scripts, CI/CD, API-запросах и проверке конфигураций.

---

### `systemctl` и `journalctl`

Базовые команды эксплуатации systemd-сервера.

* `systemctl` управляет services и показывает их состояние;
* `journalctl` читает и фильтрует системные журналы.

Именно с них обычно начинается диагностика сервиса, установленного непосредственно в Linux.

## 48. Awesome-Selfhosted и карта будущих сервисов

[Awesome-Selfhosted](https://github.com/awesome-selfhosted/awesome-selfhosted) — большой каталог свободных self-hosted приложений, а не готовая архитектура и не знак, что каждый проект подходит для постоянной эксплуатации. Раздел проверен по коммиту [`7d4d103`](https://github.com/awesome-selfhosted/awesome-selfhosted/commit/7d4d103528de45a68e63ae65c3c0f8ac431883c7) от 2026-07-28.

### Правило внедрения

```text
каталог → реальная потребность → проверка проекта → vm-lab → update/backup/restore → решение → vm-core
```

До постоянной установки проверить:

* конкретного пользователя и сценарий;
* отсутствие дублирования;
* поддержку проекта, лицензию и Docker Compose;
* потребление CPU, RAM и диска;
* модель данных, backup и проверяемый restore;
* доступ только из LAN/VPN или необходимость публикации;
* возможность удалить сервис без потери важных данных.

### Отобранные кандидаты по этапам

| Этап | Категория | Кандидаты | Комментарий |
|---|---|---|---|
| Эксплуатационный минимум | uptime, heartbeat, уведомления, dashboard | Uptime Kuma, Healthchecks, ntfy, Homepage | Добавлять по мере появления проверок и интерфейсов |
| Лёгкие домашние сервисы | закладки, RSS, PDF, рецепты | linkding/Readeck/LinkWarden; Miniflux/FreshRSS; Stirling-PDF; Mealie | В каждой категории выбрать один продукт |
| Документы | OCR и архив | Paperless-ngx | Только после готового backup/restore |
| DevOps lab | Git и automation | Forgejo, Activepieces/n8n/Node-RED, Dagu | GitHub остаётся внешним origin; automation — один инструмент под задачу |
| После NAS | sync, cloud, media, photos | Syncthing; Seafile/Nextcloud; Jellyfin; Immich; Audiobookshelf; Navidrome | Immich и sync не заменяют backup |
| Сеть | DNS и наблюдение LAN/WAN | AdGuard Home, NetAlertX, Speedtest Tracker | После стабильной сети и понятного failover |
| Умный дом | automation и камеры | HAOS, ESPHome, Mosquitto, Frigate | Камеры ждут PoE, NAS и hardware acceleration |
| Поздний lab | orchestration и AI | Swarm, k3s, Open WebUI/Ollama, AnythingLLM, Hermes | Не являются частью базовой инфраструктуры |

### Полезные развилки

* `linkding` — простой bookmark manager; Readeck — read-later и архив; LinkWarden — более тяжёлое общее хранилище ссылок.
* Miniflux — минималистичный RSS reader на Go; FreshRSS — более функциональный вариант.
* Syncthing — синхронизация папок; Seafile — сфокусированный file sync/cloud; Nextcloud — тяжёлый groupware-комбайн.
* Jellyfin — общее media streaming; Audiobookshelf — аудиокниги/подкасты; Navidrome — музыка; не обязательно ставить все три.
* Uptime Kuma показывает доступность; Healthchecks следит, что периодическая задача действительно запускалась; Prometheus хранит метрики. Они не заменяют друг друга.

### Что не добавлять в основной стек без новой причины

* CasaOS, Tipi, YunoHost и похожие one-click-платформы поверх уже выбранной схемы Proxmox → Debian → Docker Compose;
* собственный mail server;
* два-три приложения одной категории;
* SSO, Kubernetes и distributed storage до появления реальной сложности, которую они уменьшают;
* админские панели, опубликованные напрямую в интернет.

Подробная персональная карта с волнами внедрения: [[../../docs/service-catalog]].
